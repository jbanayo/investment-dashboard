# Product Requirements Document: AI Research and Monitoring

**Release:** 1.1.0  
**Status:** Released
**Owner:** J  
**Created:** 2026-09-26  
**Updated:** 2026-10-01
**Depends on:** Investment Dashboard 1.0.0

---

## 1. Summary

Version 1.1.0 adds a Research page for personal theses and AI-assisted research
that the user imports from Codex or another external agent. Each imported result
creates a reviewable research card containing a concise thesis, a suggested
action, an optional price trigger, risks, and dated source links.

AI output is always a draft. The user decides whether to keep it under active
monitoring, save it only in the research library, or archive it. The user can
also write structured research manually. Approved monitoring items appear on
the dashboard as context beside portfolio values and holdings.

The feature records research and decisions. It never places a trade.

## 2. Problem

Version 1.0 answers what is held, what it is worth, and how it has performed. It
does not capture the current investment thesis or the conditions under which a
position should be bought, held, reduced, or sold.

Research is currently scattered across articles, broker notes, memory, and
free-text position notes. It is difficult to answer:

- Why is this investment still held?
- What price or event should cause a review?
- Which thesis is based on recent evidence and which is stale?
- Which AI findings were accepted by the user and which were rejected?
- What source supported a claim at the time the decision was made?

## 3. Goals

- Import cited research drafts generated by Codex or another external agent.
- Present a clear action stance such as Buy, Hold, Reduce, Sell, Watch, or
  Avoid, with an optional price trigger and time horizon.
- Keep facts, source-backed analyst targets, and AI interpretation visibly
  distinct.
- Require human review before research affects monitoring or the dashboard.
- Let the user create the same structured research manually without AI.
- Preserve every saved or archived research version for later review.
- Show active research context on the dashboard without obscuring portfolio
  figures.
- Keep all portfolio data local; the app does not send investment data to an AI
  provider in version 1.1.0.

## 4. Non-goals

- No trade execution, order creation, or broker authentication.
- No automatic buying, selling, or portfolio rebalancing.
- No in-app AI provider, scheduled research runs, or background monitoring in
  1.1.0.
- No push, email, or mobile alerts. Trigger status is evaluated when prices are
  refreshed or the app is opened.
- No guarantee that an AI recommendation is correct or profitable.
- No replacement of the existing analyst-ratings feature. Analyst consensus is
  third-party data; AI research is a separate user-reviewed artifact.
- No personalized tax, legal, or regulated financial advice.
- No hidden deletion of prior research. Archive retains the record.

## 5. Product Principles

### 5.1 Human approval controls state

An external AI agent may propose. Only the user may place an item into active
monitoring. An imported result cannot modify ratings, position notes,
transactions, targets, or dashboard monitoring without a deliberate action on
that individual card.

### 5.2 Sources before conclusions

Every AI card must show the sources used, their publication dates when known,
and the time they were accessed. Material factual claims should be traceable to
one or more sources. A card without usable sources is marked incomplete and
cannot be kept for monitoring until the user accepts the limitation.

### 5.3 Research is versioned

Each import creates a new draft. It never overwrites a saved thesis or silently
changes a target. User edits and status changes are recorded as events.

### 5.4 Suggestions are conditions, not commands

The product language is “suggested stance” and “review trigger.” A target such
as “Sell above $250” means “review this thesis when the condition is reached.”
It does not create or imply an order.

### 5.5 Local-first privacy

The app makes no external research requests. The user controls what they share
with an external agent, and imports only the resulting structured thesis and
source metadata back into the local database.

## 6. Primary User Flow

1. The user opens **Research** from the main navigation.
2. The user either writes a thesis manually or asks Codex or another agent to
   research an instrument using the provided prompt.
3. For external AI research, the user saves the returned Markdown and uploads
   it through **Upload AI findings**.
4. The app previews the parsed instrument, thesis, stance, triggers, risks, and
   sources. The user confirms the import, which creates a draft.
5. The user reviews the draft in the **Review inbox**.
6. The user chooses one outcome:
   - **Keep monitoring** — save the card and make it active on the dashboard.
   - **Save research** — retain it in the library without active monitoring.
   - **Archive** — retain it outside active and default library views.
7. When a monitored price condition is met, the item is marked **Review due**
    after the next price refresh or dashboard load.

## 7. Research Page

The current design is
[`v1.1.0-research-prototype.2.html`](prototypes/research/v1.1.0-research-prototype.2.html).
Prototype iterations are indexed in [`prototypes/README.md`](prototypes/README.md)
and are not overwritten when the design changes.

### 7.1 Page structure

The Research page contains:

- **AI research guide** — choose an instrument, copy a ready-made prompt, and
  see the required Markdown format before leaving for Codex or another agent.
- **Upload AI findings** — accepts one `.md` or `.markdown` file and previews
  the parsed thesis before creating a draft.
- **Review inbox** — new AI drafts requiring a decision.
- **Monitoring** — user-approved active research and trigger status.
- **Saved** — accepted research that is not actively monitored.
- **Archived** — retained historical items, hidden by default.
- **Add manual research** — a form that creates a user-authored card.

Filters apply across tabs:

- Platform: All, Kraken, BDO Securities, IBKR.
- Instrument.
- Stance.
- Status.
- Source: AI or manual.
- Research date.

### 7.2 Research card

Each card displays:

- Instrument name, ticker, platform, and asset class.
- Research date and “as of” market-data date.
- Origin: AI-assisted import or manual.
- Suggested stance: Buy, Hold, Reduce, Sell, Watch, or Avoid.
- Optional review trigger:
  - price at or below,
  - price at or above,
  - or a text-only event condition.
- Target price and currency, if used.
- Time horizon: short term, 6–12 months, long term, or custom date.
- Thesis summary.
- Key supporting points.
- Key risks and thesis breakers.
- Confidence: Low, Medium, or High, with a short explanation.
- Current price and distance to the trigger.
- Source list with title, publisher, publication date, and link.
- Status and status history.

The card must clearly label an AI-created price target as **AI suggestion**. A
target copied from an analyst source is labelled **Source target** and retains
the source name. Neither is written into the existing analyst-ratings table
unless the user separately records it as a rating.

### 7.3 Card actions

**Keep monitoring**

- Saves the card.
- Sets it as the active monitoring thesis for that instrument.
- Displays it on the dashboard.
- Supersedes, but does not delete, an older active thesis for the same
  instrument after user confirmation.

**Save research**

- Saves the card to the library.
- Does not display it as an active dashboard signal.
- Can later be promoted to monitoring.

**Archive**

- Retains the card, sources, and audit events.
- Removes it from the review inbox, monitoring, saved default view, and
  dashboard.
- Can be restored.

**Edit**

- Allows the user to change stance, trigger, horizon, summary, risks, and
  source metadata before or after saving.
- Preserves the original AI response and records the edited version.

## 8. Manual Research

The manual form uses the same structured fields as an AI card:

- Instrument.
- Research date.
- Stance.
- Trigger type, price, and currency.
- Time horizon.
- Thesis.
- Supporting points.
- Risks or invalidation conditions.
- Optional article links or uploaded documents.

Example:

> Ayala Corporation — Hold. Review for sale if AC reaches PHP 720, unless
> earnings growth or the property outlook materially improves first.

Manual research may be saved directly to Monitoring, Saved, or Draft. It does
not require an external agent or an external source, but the UI should
distinguish a personal thesis from a sourced factual claim.

## 9. AI-Assisted Research Import

### 9.1 Trigger and scope

- The user asks Codex or another external AI agent to research an instrument.
- The Research page provides a copyable prompt that names the selected
  instrument and embeds the current Markdown template.
- The user saves the agent's answer as a `.md` or `.markdown` file and uploads
  it to the app.
- The app parses and previews the result, validates required metadata and source
  URLs, then creates one independent Draft card only after user confirmation.
- Cash instruments and synthetic dividend accruals are excluded.
- The app makes no AI or web-search API calls in version 1.1.0.

### 9.2 Research inputs

The supplied agent prompt requests only public research and a structured
Markdown result. The user decides what context to provide to the external
agent. The app itself never sends quantities, cost basis, account values,
account identifiers, or statement filenames outside the local database.

### 9.3 Markdown file contract

The import format is Markdown with YAML frontmatter. The frontmatter contains
machine-readable fields while the document body stays readable in Codex, Git,
or any text editor.

Required frontmatter:

- `format_version` — initially `1`.
- `instrument` and `ticker`.
- `research_date`.
- `stance` — buy / hold / reduce / sell / watch / avoid.
- `confidence` — low / medium / high.
- `time_horizon`.
- `trigger_type` — none / at_or_below / at_or_above / event.

Conditional frontmatter:

- `trigger_price` and `trigger_currency` for numeric triggers.
- `event_trigger` for event triggers.
- `source_target`, `source_target_currency`, and `source_target_issuer` when a
  published source explicitly states a target.

Required body headings:

- `# Thesis`
- `## Supporting points`
- `## Risks`
- `## Sources`

Sources use ordinary Markdown links and may add publisher, publication date,
and source type after the link. The parser accepts headings case-insensitively,
normalizes whitespace, and rejects ambiguous duplicate sections.

Upload rules:

- One UTF-8 `.md` or `.markdown` file per import.
- Maximum file size: 1 MB.
- Raw HTML, scripts, embedded remote media, and executable content are ignored.
- Instrument ticker must match the instrument selected in the app.
- The preview shows every parsed field and validation warning before import.
- Invalid files do not create partial database records.

### 9.4 Source quality

The research process should prefer:

1. Company filings and investor-relations releases.
2. Exchange disclosures and regulator filings.
3. Earnings transcripts and official presentations.
4. Reputable financial news and established research providers.
5. Other sources only when clearly identified.

Sources must be relevant to the instrument and claim. Search-result snippets
alone are insufficient. Duplicate syndicated articles should count as one
source. Publication date and access date are stored separately.

For fast-moving claims such as earnings, management guidance, legal events, or
crypto protocol incidents, the external research should favor recent sources.
Older sources may be used for long-term background and must remain visibly
dated.

### 9.5 Recommendation rules

- A stance must include a rationale and risks.
- A numeric trigger must include currency and time horizon.
- The AI may return no numeric target when evidence does not support one.
- A card must not invent analyst consensus or attribute a target to a source
  that does not state it.
- Conflicting evidence is summarized rather than silently resolved.
- If the local current price is stale, the card displays a stale-price warning.
- A failed file import does not alter existing research.

### 9.6 External-agent boundary

The app provides a reusable prompt and Markdown upload form. It stores the
original uploaded Markdown, filename, declared format version, agent name,
parsed fields, and source metadata locally. This makes the imported artifact
auditable after later edits. It does not store API credentials, make provider
requests, or retain hidden chain-of-thought.

## 10. Monitoring Logic

Active price conditions are evaluated:

- After **Refresh prices** completes.
- When the dashboard or Research page loads.

Statuses are:

- **Watching** — condition has not been met.
- **Review due** — current price meets the configured condition.
- **Price stale** — the condition cannot be trusted because the price is stale.
- **No price** — no compatible price is available.
- **Expired** — the monitoring horizon ended without renewal.

Reaching a trigger does not change the stance, archive the item, or create a
transaction. The user may revise, replace, save, or archive the thesis after
review.

Event-only triggers are manually marked due in 1.1.0. Automated news/event
detection is deferred.

## 11. Dashboard Integration

The approved dashboard design is captured in
[`v1.1.0-dashboard-research-prototype.html`](v1.1.0-dashboard-research-prototype.html).
Portfolio numbers remain the visual priority. Research is incorporated in three
places:

1. **Research navigation count.** The Research navigation item shows the number
   of drafts awaiting review. It is a link to the inbox, not a recommendation.
2. **Holdings research column.** Each non-cash holding with an active thesis
   shows its approved stance, monitoring status, trigger, and approval date.
   Holdings without one explicitly say “No monitored thesis.” The analyst
   rating remains a separate field and is never replaced by AI research.
3. **Research monitoring section.** A section below Holdings contains the
   approved items that need attention or are closest to a trigger, plus a small
   inbox summary.

The **Research monitoring** section contains:

- An attention message when one or more triggers are due.
- Up to five monitored items, ordered Review due, Price stale, Expired, then
  nearest numeric trigger.
- Instrument, stance, trigger, current price, distance to trigger, and research
  date.
- A compact inbox card with draft, stale, and monitoring counts.
- Links to review an individual thesis or open the complete Research page.

Clicking an approved research entry opens a compact detail dialog with stance,
trigger, status, thesis summary, monitoring rationale, and a link to the full
source history. Stopping monitoring or changing the thesis happens through the
Research workflow and is recorded as an event.

Platform filtering applies to research just as it applies to holdings. Selecting
IBKR shows only IBKR monitoring items; All platforms shows the combined list.

The dashboard never displays unreviewed AI output as an accepted recommendation.
Drafts appear only as an inbox count and a link to review them. Research does
not alter allocation, portfolio value, return, or transaction data.

## 12. Data Model

### `research_items`

- `id`
- `instrument_id` → instruments
- `origin` — ai / manual
- `status` — draft / monitoring / saved / archived
- `stance` — buy / hold / reduce / sell / watch / avoid
- `research_date`
- `market_price`
- `market_price_date`
- `trigger_type` — at_or_below / at_or_above / event / none
- `trigger_price`
- `trigger_currency`
- `event_trigger`
- `time_horizon`
- `expires_on`
- `summary`
- `supporting_points_json`
- `risks_json`
- `confidence`
- `confidence_reason`
- `source_target`
- `source_target_currency`
- `source_target_issuer`
- `original_payload_json`
- `created_at`
- `updated_at`

Only one item per instrument may have `status = monitoring`. Replacing it
creates an audit event and moves the prior item to Saved unless the user chooses
Archive.

### `research_imports`

- `id`
- `research_item_id` → research_items, unique
- `format` — markdown
- `format_version`
- `filename`
- `agent_name`, nullable
- `raw_content`
- `normalized_payload_json`
- `imported_at`

Each confirmed AI-assisted import has one immutable import record. Editing the
research card changes the working thesis while preserving the uploaded artifact.

### `research_import_previews`

- `id` — unguessable preview token
- `instrument_id` → instruments
- `filename`
- `agent_name`, nullable
- `raw_content`
- `normalized_payload_json`
- `warnings_json`
- `created_at`
- `expires_at`

The server stores previews temporarily so confirmation does not trust hidden
browser fields. Confirmation reparses and validates the staged file in one
transaction, creates the Draft and import record, then removes the preview.
Expired previews are deleted automatically.

### `research_sources`

- `id`
- `research_item_id` → research_items
- `title`
- `publisher`
- `url`
- `published_at`
- `accessed_at`
- `document_id` → documents, nullable
- `source_type` — filing / company / exchange / news / research / other

### `research_events`

- `id`
- `research_item_id` → research_items
- `event_type` — generated / edited / monitoring / saved / archived / restored /
  trigger_met / trigger_cleared / expired
- `from_status`
- `to_status`
- `detail`
- `event_at`

The existing `research_runs`, `research_items.run_id`, and `watchlist` schema
may remain for migration compatibility, but version 1.1.0 does not read or
write them. Direct provider runs and a separate watchlist are deferred.

## 13. Functional Requirements

### P0 — required for 1.1.0

- [x] Research appears in the main navigation.
- [x] User can select an existing instrument when importing AI-assisted research.
- [x] User can upload a structured Markdown research file.
- [x] User can preview parsed findings and validation warnings before import.
- [x] Confirmed uploads create a Draft card with source links.
- [x] User can edit a draft before choosing an outcome.
- [x] User can Keep monitoring, Save research, or Archive each card.
- [x] User can create equivalent structured research manually.
- [x] Active numeric triggers are evaluated against locally stored prices.
- [x] Dashboard displays approved monitoring only.
- [x] AI and analyst-rating targets remain separate.
- [x] Archived and superseded research remains readable.
- [x] No AI credentials are required or stored; portfolio data remains outside Git.
- [x] Reset local data removes research records and staged imports.
- [x] Database export includes all research, sources, and audit events.

### P1 — desirable after the core flow

- [ ] Compare a new draft with the current monitored thesis.
- [ ] Generate a replacement research prompt from an existing card.
- [x] Duplicate-source detection within one imported result.
- [ ] Upload a PDF or image as a manual research source.
- [ ] Export a research card with its sources as Markdown.
- [ ] Show historical outcomes: trigger reached, price at archive, and later
  performance, clearly separated from causal claims.

### Deferred beyond 1.1.0

- Scheduled research.
- Email, push, or operating-system notifications.
- Automated event-trigger detection.
- Portfolio-level allocation recommendations.
- Trade tickets or broker integration.
- Social sentiment scoring.
- Automatic acceptance of AI output.
- Separate instrument watchlists that are not tied to a portfolio holding.

## 14. Error and Empty States

- No external agent available: manual research remains fully usable and the
  import page provides a reusable agent prompt.
- Invalid Markdown: preserve existing research and explain which frontmatter
  field, required section, ticker, or source URL needs attention.
- No sources: mark the draft Incomplete and explain why.
- No current price: allow qualitative research, disable numeric distance and
  trigger evaluation.
- Stale current price: show the price date and warning on the card.
- Deleted instrument: blocked while research references it, consistent with
  existing transaction and rating protections.

## 15. Security and Privacy

- URLs are rendered as links, never executed as HTML supplied by the model.
- AI text and source metadata are treated as untrusted input and escaped by the
  templates.
- Raw HTML, JavaScript URLs, embedded remote media, and executable content are
  discarded during parsing and never rendered.
- Structured output is schema-validated before database writes.
- The app does not store AI API credentials or make AI provider requests.
- Account numbers and source statement filenames are never sent by the app.

## 16. Success Measures

The release is successful when:

- A user can import a source-linked external AI research draft for any existing
  instrument.
- Every dashboard research signal can be traced to a user-approved card.
- No import changes transactions, ratings, or monitoring without user action.
- A manual Ayala sell-review thesis can be entered and evaluated against future
  refreshed prices.
- A week without opening the app does not lose trigger evaluation; the next
  price refresh backfills prices and updates monitoring status.
- Archived and superseded theses remain auditable.

## 18. Acceptance Scenarios

### Scenario A — AI draft becomes monitored research

Given Apple is an existing IBKR holding, when the user imports a cited Hold
draft from Codex with a $250 review trigger, then no dashboard signal
appears until the user clicks Keep monitoring. After approval, the Apple
monitoring card and dashboard badge show Hold, $250, the price date, and links to
the approved sources.

### Scenario B — AI draft is rejected

Given an NVIDIA draft is in the review inbox, when the user archives it, then it
does not appear on the dashboard or monitoring list, but remains available in
Archived with its original output and sources.

### Scenario C — Manual Ayala thesis

Given Ayala Corporation exists in the BDO portfolio, when the user manually
records “Hold; review for sale at PHP 720” and chooses Keep monitoring, then the
dashboard displays the thesis. When a later PSE price refresh reaches or exceeds
PHP 720, its status changes to Review due without creating a sell transaction.

### Scenario D — Invalid AI findings file

Given a user uploads a valid cited Markdown file for one instrument, its parsed
preview appears before confirmation and the confirmed draft enters the inbox.
Invalid frontmatter, missing sections, ticker mismatches, or source URLs are
rejected without changing existing research.

### Scenario E — New import does not overwrite the current thesis

Given Apple already has an active monitored thesis, when a later imported AI
draft proposes a different thesis, the existing thesis remains active. Only
explicit user approval replaces it, and the previous thesis moves to Saved or
Archived based on the user's choice.

## 19. Version 1.1.0 Decision: External-agent Import

Version 1.1.0 uses manual entry and externally generated AI research imports.
Codex is the preferred first research agent, but any agent can be used when it
returns the documented Markdown shape. Direct provider integration, API
billing, and automatic web search remain future work.

The app preserves the uploaded Markdown as the original research artifact. For
each cited external source, it stores only title, publisher, URL, source type,
publication date when known, and access date. It does not download or store
article bodies or search-result excerpts. A draft with no sources is visibly
marked **Incomplete · no verified sources** and cannot be mistaken for a fully
sourced result.
