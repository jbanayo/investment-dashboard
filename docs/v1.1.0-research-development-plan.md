# Version 1.1.0 Research Development Plan

**Status:** Approved for development

**Updated:** 2026-09-27

**PRD:** [`v1.1.0-ai-research-prd.md`](v1.1.0-ai-research-prd.md)

**Design baseline:** [`Prototype 2`](prototypes/research/v1.1.0-research-prototype.2.html)

## 1. Starting Point

The application already has the research navigation, database foundation,
manual research form, Draft/Monitoring/Saved/Archived workflow, source records,
audit events, trigger evaluation, and initial dashboard integration. It also has
an interim pasted-JSON importer. Version 1.1.0 will replace that importer with
the approved external-agent Markdown workflow.

Existing manual research and monitoring behavior must remain usable throughout
development. Each phase ends in a testable application state.

## 2. Delivery Phases

### Phase 1 — Import model and versioned contract

**Status:** Complete

**Outcome:** The application has a documented and testable Markdown contract
and can preserve the exact artifact that produced a research draft.

- Add migrations for immutable `research_imports` and temporary
  `research_import_previews` records.
- Add reset and database-export coverage for both tables.
- Add a canonical version 1 Markdown template and one valid example fixture.
- Define supported stance, confidence, trigger, date, source, and heading rules
  in one parser module rather than duplicating them in routes or templates.
- Leave legacy provider-run and watchlist tables unused for migration
  compatibility.

**Acceptance:** A migrated version 1.0 database opens successfully; export and
reset include the new records; the contract fixture is readable by a person and
contains every required field.

### Phase 2 — Safe Markdown parser and validator

**Status:** Complete

**Outcome:** A Markdown file can be converted into a normalized research draft
without writing a research item.

- Parse YAML frontmatter and the four required body sections.
- Enforce UTF-8, `.md`/`.markdown`, 1 MB, format version, selected-ticker match,
  conditional trigger fields, and valid HTTP/HTTPS source links.
- Normalize lists, whitespace, dates, currencies, and case-insensitive headings.
- Reject duplicate or ambiguous required sections.
- Discard raw HTML, scripts, embedded media, and unsafe URL schemes.
- Return field-specific errors and non-blocking warnings for the preview.

**Acceptance:** Unit tests cover a valid import plus malformed frontmatter,
missing sections, duplicate sections, ticker mismatch, invalid triggers,
unsafe URLs, invalid UTF-8, and oversized files. Invalid input performs no
persistent research write.

### Phase 3 — Agent guide, upload, and preview

**Status:** Complete

**Outcome:** The Research page matches prototype 2 through the preview step.

- Add instrument selection, optional research focus, and optional agent name.
- Generate a copyable prompt containing the selected instrument and canonical
  Markdown template.
- Provide Copy prompt and Download template actions.
- Add accessible file selection and drag-and-drop upload.
- Stage the server-validated file under an expiring, unguessable preview token.
- Show all parsed fields, sources, errors, and warnings before confirmation.
- Let the user cancel a preview without creating a Draft.

**Acceptance:** A user can select Apple, copy its prompt, upload the example
Markdown, and see an accurate preview. Reloading or modifying browser form data
cannot change the server-staged result. No card appears before confirmation.

### Phase 4 — Confirmed import and review workflow

**Status:** Complete

**Outcome:** Confirming a preview creates one auditable AI-assisted Draft.

- Revalidate the staged import at confirmation.
- In one transaction, create the research item, sources, immutable import
  artifact, and generated audit event; then delete the preview.
- Label imported cards as AI-assisted and show filename, agent, format version,
  research date, and source links.
- Replace the interim pasted-JSON importer and remove its UI and route paths.
- Preserve Edit, Keep monitoring, Save research, Archive, restore, and
  superseding behavior.
- Show the original imported Markdown separately from the user-edited thesis.

**Acceptance:** Confirmation creates exactly one Draft even after a repeated
submit. Cancelling, expiry, or validation failure creates none. Later edits do
not change the original imported artifact.

### Phase 5 — Dashboard and monitoring completion

**Outcome:** Approved research complements the portfolio without changing its
financial calculations.

- Finish the Research navigation inbox count and dashboard monitoring section.
- Show approved stance and trigger context on applicable holdings.
- Apply platform filtering consistently to research and holdings.
- Order monitoring by Review due, Price stale, Expired, then distance to trigger.
- Add the compact research detail dialog and links to full history.
- Verify evaluation after price refresh and dashboard/Research page load.

**Acceptance:** Draft and Saved items never appear as accepted dashboard
signals. A monitored Ayala at-or-above trigger becomes Review due when the local
price reaches it, without creating or changing a transaction.

### Phase 6 — Release hardening and version 1.1.0

**Outcome:** The feature is safe to migrate, understandable to install, and
ready to release.

- Complete keyboard, focus, screen-reader label, responsive-layout, empty-state,
  and error-state checks.
- Test migrations from a version 1.0 database and a fresh database.
- Run the full automated suite and a manual browser pass in light and dark mode.
- Verify that database backup/export and reset behave correctly.
- Update README setup, research workflow, privacy boundary, import template, and
  troubleshooting instructions.
- Set the application version to 1.1.0 and record release notes.

**Acceptance:** All automated checks pass; the five PRD acceptance scenarios
pass in the browser; no AI credential is requested; no import sends portfolio
data over the network.

## 3. Work Sequence

| Order | Phase | Depends on | Review checkpoint |
| --- | --- | --- | --- |
| 1 | Import model and contract | Current research foundation | Inspect migration and example Markdown |
| 2 | Parser and validator | Phase 1 | Review validation matrix and test results |
| 3 | Guide, upload, preview | Phase 2 | Compare browser UI with prototype 2 |
| 4 | Confirmed import | Phases 1–3 | Import, edit, archive, and restore one draft |
| 5 | Dashboard completion | Phase 4 | Validate platform filters and trigger behavior |
| 6 | Release hardening | All prior phases | Run release checklist and migration rehearsal |

## 4. Definition of Done

Version 1.1.0 is complete when the PRD P0 list is checked, the Markdown import
is the only AI-assisted ingestion path, the original upload remains auditable,
the dashboard shows only user-approved monitoring, all tests pass, and the
installation and import workflow are documented for a fresh local setup.

Direct AI APIs, scheduled research, automatic event detection, notifications,
and a separate watchlist remain future work.
